# 安全威胁模型（STRIDE 分析）

> 版本: v1.0 | 日期: 2026-07-25
>
> 关联文档: [架构设计](caddy-multi-tenant-architecture.md) | [测试策略](test-strategy.md)

## 1. 概述

本文档使用 STRIDE 框架对 Portunus 进行系统性的安全威胁分析，识别潜在威胁并制定缓解措施。

### 1.1 系统边界

```
┌─────────────────────────────────────────────────────────┐
│                    Portunus 系统                          │
│                                                          │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐            │
│  │ 前端 Web  │   │ 控制面 API │   │ MCP Server │            │
│  │ (React)  │   │ (Go/Gin)  │   │ (MCP SDK) │            │
│  └────┬─────┘   └─────┬────┘   └─────┬────┘            │
│       │               │              │                   │
│       │         ┌─────┴────┐         │                   │
│       │         │ PostgreSQL│         │                   │
│       │         │  Redis    │         │                   │
│       │         │  MinIO    │         │                   │
│       │         └──────────┘         │                   │
│       │                               │                   │
│  ─────┴───────────────────────────────┴──────────         │
│                    mTLS + admin.identity + admin.origins  │
│  ┌─────────────────────────────────────────────┐         │
│  │            Caddy 数据面 (Admin API)            │         │
│  └─────────────────────────────────────────────┘         │
└─────────────────────────────────────────────────────────┘
        ↑                              ↑
    用户（HTTPS）                  AI Agent（MCP/SSE）
```

### 1.2 信任边界

| 边界 | 说明 |
|---|---|
| 外部 → 前端 | 互联网用户通过 HTTPS 访问前端 |
| 前端 ↔ 控制面 API | 前端通过 HTTPS/TLS 调用控制面 API，需防止 TLS 剥离和参数篡改 |
| 前端 → 控制面 | 前端通过 HTTP 调用控制面 API |
| 控制面 ↔ Caddy | 控制面通过 mTLS 调用 Caddy Admin API |
| 控制面 ↔ MCP Server | 控制面与 MCP Server 之间通过 MCP 协议交互，需校验调用来源和工具权限 |
| 控制面 ↔ 任务调度器 | 控制面触发/管理异步任务，需认证任务生产者并防止任务伪造 |
| 控制面 → 数据库 | 控制面通过 PostgreSQL 连接 |
| AI Agent → 控制面 | AI 通过 MCP 协议调用控制面 |
| Caddy 数据面 ↔ Caddy Admin API | Caddy 数据面与 Admin API 分离，Admin API 仅允许受信控制面访问 |
| CI/CD ↔ 生产环境 | CI/CD 通过临时凭证和最小权限部署到生产，禁止持久密钥 |
| 项目 A → 项目 B | 多租户之间的数据隔离边界 |

## 2. STRIDE 威胁分析

### S — Spoofing（欺骗）

| # | 威胁 | 场景 | 严重度 | 缓解措施 | 状态 |
|---|---|---|:---:|---|:---:|
| S1 | JWT 伪造 | 攻击者伪造或篡改 JWT 访问他人项目 | 高 | RS256 签名 + 过期检查 + Redis 撤销列表 | ✅ |
| S2 | 密码暴力破解 | 攻击者反复尝试密码登录 | 中 | 连续 5 次失败锁定 15 分钟 + Argon2id 慢哈希 | ✅ |
| S3 | Caddy Admin API 伪造 | 攻击者直接访问 Caddy :2021 | 高 | mTLS 双向认证 + `admin.identity`（mTLS 证书） + `admin.origins`（来源限制） + 端口不暴露 | ✅ |
| S4 | API Token 伪造 | 攻击者猜测或暴力枚举 Token | 高 | 256-bit 随机生成 + SHA-256 哈希存储 + 仅展示一次 | ✅ |
| S5 | OAuth 会话劫持 | CSRF 攻击劫持 OAuth 回调 | 中 | state 参数校验 + PKCE | ⚠️ 阶段2 |
| S6 | 邀请链接劫持 | 攻击者截获邀请链接加入项目 | 中 | JWT 签名 + 24h 过期 + 一次性使用 | ✅ |

### T — Tampering（篡改）

| # | 威胁 | 场景 | 严重度 | 缓解措施 | 状态 |
|---|---|---|:---:|---|:---:|
| T1 | @id 路径注入 | 攻击者在 @id 中注入 `../../` 访问他人配置 | 高 | 正则校验 `^[a-zA-Z0-9_-]+$` + 路径白名单 | ✅ |
| T2 | 配置注入 | 攻击者在 Caddy JSON 中注入恶意配置 | 高 | JSON Schema 校验 + `POST /load` 试加载 + 字段白名单 | ✅ |
| T3 | SQL 注入 | 攻击者在查询参数中注入 SQL | 高 | sqlc 参数化查询 + entityTableMap 白名单 | ✅ |
| T4 | 并发配置覆盖 | 两个用户同时修改同一配置 | 中 | 应用层乐观锁：在配置元数据中维护 version 字段，更新时校验；Caddy 层面通过 /id/<name> 路径 + If-Match 头进行细粒度并发控制 | ✅ |
| T5 | 审计日志篡改 | 攻击者修改审计日志掩盖痕迹 | 高 | 数据库 INSERT ONLY（无 UPDATE/DELETE 权限） | ⚠️ 需DB角色 |
| T6 | 配置漂移 | Caddy 运行态被直接修改 | 中 | checksum 定时比对 + 漂移告警 | ⚠️ 阶段3 |
| T7 | @id 篡改 | 用户修改请求路径中的 @id 访问他人资源 | 高 | @id 归属校验中间件 + 前缀匹配 + DB 二次确认 | ✅ |
| T8 | TLS 剥离 | 中间人或 AI 调用链路中 TLS 被降级为明文 | 高 | 强制 TLSv1.3 + HSTS + 证书固定 + 出站请求 TLS 校验 | ✅ |
| T9 | 请求参数篡改 | AI Agent 篡改 MCP/REST 请求参数越权操作 | 高 | 参数签名 + 服务端参数校验 + 操作范围限制 | ✅ |
| T10 | Redis 数据篡改 | 攻击者篡改 Redis 中令牌、限流状态等数据 | 中 | Redis 认证 + TLS 传输 + 关键数据签名/校验 | ✅ |
| T11 | CI/CD 构建产物篡改 | 构建产物在仓库或镜像仓库中被替换 | 高 | 构建签名 + SBOM 校验 + 镜像扫描 + 不可变 artifact 仓库 | ✅ |

### R — Repudiation（否认）

| # | 威胁 | 场景 | 严重度 | 缓解措施 | 状态 |
|---|---|---|:---:|---|:---:|
| R1 | 操作否认 | 用户否认执行了某配置变更 | 高 | 全操作审计日志（含 IP、UA、时间、请求体） | ✅ |
| R2 | AI 操作否认 | 用户否认 AI 代表其执行了操作 | 高 | MCP 工具调用记录在审计日志（via=mcp_tool） | ✅ |
| R3 | 日志丢失 | 审计日志因系统故障丢失 | 高 | 审计日志与业务操作在同一事务内写入 | ✅ |
| R4 | 请求来源否认 | 攻击者否认请求来源 | 中 | request_id 贯穿日志 + IP 记录 | ✅ |

### I — Information Disclosure（信息泄露）

| # | 威胁 | 场景 | 严重度 | 缓解措施 | 状态 |
|---|---|---|:---:|---|:---:|
| I1 | 横向越权信息泄露 | 用户 A 查看项目 B 的域名配置 | 高 | @id 归属校验 + RBAC 中间件 | ✅ |
| I2 | 错误信息泄露 | 错误响应暴露内部架构（如 SQL 错误） | 中 | 统一错误码 + 生产环境隐藏堆栈 | ✅ |
| I3 | 日志敏感信息 | 密码、Token 出现在日志中 | 高 | 敏感字段标记 + 日志脱敏中间件 | ⚠️ 需实现 |
| I4 | API Token 明文存储 | 数据库泄露导致 Token 泄露 | 高 | SHA-256 哈希存储 + 仅创建时展示 | ✅ |
| I5 | Caddy 配置泄露 | Caddy :2021 被扫描获取配置 | 高 | mTLS + 端口不暴露 + `admin.origins` | ✅ |
| I6 | 数据库备份泄露 | 备份文件未加密 | 高 | 备份加密 + MinIO 访问控制 | ⚠️ 需配置 |
| I7 | 前端源码泄露 | 生产环境暴露 source map | 低 | 生产构建禁用 source map | ⚠️ 需配置 |
| I8 | AI Agent 泄露敏感配置 | AI Agent 在日志/提示中暴露数据库连接串、密钥 | 高 | 敏感配置标记 + 日志脱敏 + AI 上下文最小化 + 密钥轮换 | ⚠️ 需实现 |
| I9 | 时序攻击 | 通过响应时间差异推断用户/配置存在性 | 中 | 恒定时间比较 + 响应时间归一化 + 速率限制 | ✅ |
| I10 | .git 泄露 | 生产部署暴露 `.git` 目录 | 中 | 部署流程排除 `.git` + WAF 规则 + 扫描检查 | ✅ |
| I11 | MinIO bucket 公开 | 存储桶 ACL 配置错误导致数据公开 | 高 | bucket 私有 + 签名 URL + 访问审计 | ⚠️ 需配置 |
| I12 | 日志采样丢失 | 高频采样导致安全事件日志被丢弃 | 中 | 安全日志全量保留 + 独立采样策略 | ⚠️ 需实现 |

### D — Denial of Service（拒绝服务）

| # | 威胁 | 场景 | 严重度 | 缓解措施 | 状态 |
|---|---|---|:---:|---|:---:|
| D1 | API 限流绕过 | 攻击者高频请求耗尽资源 | 高 | Redis 令牌桶限流（按用户+按IP） | ✅ |
| D2 | Caddy Admin API 过载 | 大量配置变更请求压垮 Caddy | 中 | 控制面队列化 + 超时熔断 | ⚠️ 需实现 |
| D3 | 数据库连接耗尽 | 大量请求耗尽连接池 | 高 | 连接池限制 + 查询超时 + 熔断 | ✅ |
| D4 | 慢查询攻击 | 攻击者构造复杂查询拖慢 DB | 中 | 查询超时 + EXPLAIN 监控 | ⚠️ 需监控 |
| D5 | MCP 工具滥用 | AI Agent 高频调用 MCP 工具 | 中 | MCP 工具调用限流 + Human-in-the-loop 确认 | ✅ |
| D6 | 大配置快照 | 攻击者创建大量域名导致快照爆炸 | 中 | 配额限制 + 快照保留数量上限 | ✅ |
| D7 | L3/L4 DDoS | 针对网络层的 SYN Flood、UDP 放大等攻击 | 高 | 云厂商 DDoS 防护 + 负载均衡 + 流量清洗 | ✅ |
| D8 | ACME 限流耗尽 | 恶意请求触发 Let's Encrypt 等 CA 限流 | 中 | 证书申请限流 + 缓存证书 + 失败重试退避 | ✅ |
| D9 | Caddy 配置重载风暴 | 高频配置变更导致 Caddy 反复重载 | 中 | 配置批量提交 + 队列化 + 重载频率限制 | ⚠️ 需实现 |
| D10 | ReDoS | 正则表达式灾难性回溯导致 CPU 耗尽 | 中 | 严格正则审计 + 超时 + 避免嵌套量词 | ✅ |
| D11 | 大 JSON 配置 | 上传超大 JSON 配置导致解析/内存耗尽 | 中 | JSON 大小限制 + 字段深度限制 + 流式解析 | ✅ |
| D12 | SSE 长连接耗尽 | AI Agent MCP/SSE 长连接占用大量连接 | 中 | 连接数上限 + 心跳超时 + 优雅关闭 | ⚠️ 需实现 |

### E — Elevation of Privilege（权限提升）

| # | 威胁 | 场景 | 严重度 | 缓解措施 | 状态 |
|---|---|---|:---:|---|:---:|
| E1 | 角色提升 | viewer 通过某种方式获得 admin 权限 | 高 | RBAC 中间件 + RequireRole 装饰器 | ✅ |
| E2 | @id 前缀伪造 | 用户伪造 @id 前缀访问他人资源 | 高 | 前缀从 JWT 提取（非请求参数）+ DB 二次确认 | ✅ |
| E3 | 共享权限提升 | 被共享方从 read_only 提升为 edit | 高 | 共享权限校验中间件 + 权限矩阵 | ✅ |
| E4 | API Token 权限扩大 | Token 超出 scope 执行操作 | 高 | Token scope 校验中间件 | ✅ |
| E5 | owner 自我移除 | owner 移除自己导致项目无 owner | 中 | owner 不可被移除（需先转移所有权） | ✅ |
| E6 | 项目冻结绕过 | 冻结项目后用户仍能操作 | 高 | 冻结检查中间件 + JWT 撤销 | ✅ |
| E7 | system_admin 提权 | system_admin 获取任意项目 owner | 中 | system_admin 仅管理操作，不可成为项目 owner | ✅ |

## 6. 安全事件响应

### 6.1 告警规则

| 告警 | 条件 | 响应动作 |
|---|---|---|
| 暴力破解 | 同一 IP 5 分钟内 10+ 次 401 | 封禁 IP 30 分钟 |
| 越权尝试 | 同一用户 5 分钟内 3+ 次 403 | 通知 system_admin |
| @id 篡改 | 检测到 `../` 或非法字符 | 记录安全日志 + 告警 |
| 配置注入 | JSON Schema 校验失败 3+ 次 | 临时封禁用户 |
| Caddy 不可达 | 健康检查连续失败 3 次 | 告警 + 状态标记 |

### 6.2 事件响应流程

```
检测 → 告警 → 分类 → 遏制 → 根除 → 恢复 → 复盘
                                    │
                                    ▼
                              审计日志分析
                              影响评估
                              补丁修复
```

#### 事件分级

| 级别 | 判定标准 | 示例 | 响应时限 | 处置目标 |
|:---:|---|---|---|---|
| P0 | 核心安全功能失效、大规模数据泄露、生产环境被攻陷 | 租户隔离失效、Caddy Admin API 被未授权访问 | 1 小时内响应 | 遏制影响、恢复服务、启动复盘 |
| P1 | 单一组件严重漏洞、局部越权或数据泄露、服务可用性受损 | RBAC 绕过、JWT 伪造利用、API 限流被击穿 | 4 小时内响应 | 修复漏洞、验证缓解措施 |
| P2 | 配置缺陷、低危漏洞、监控告警误报或潜在风险 | source map 泄露、日志敏感信息未脱敏 | 24 小时内响应 | 修复并加固、更新检测规则 |

#### RACI 责任矩阵

| 阶段 | 安全负责人 | 开发团队 | 运维团队 | 法务/合规 | 高管 |
|---|---|:---:|:---:|:---:|:---:|
| 检测与分类 | A | C | C | I | I |
| 遏制与隔离 | A | C | R | C | I |
| 根因分析与根除 | C | A | C | I | I |
| 恢复与验证 | C | R | A | C | I |
| 通报与复盘 | A | C | C | R | A |

> A = 负责（Accountable），R = 执行（Responsible），C = 咨询（Consulted），I = 知会（Informed）

#### 响应时限

| 阶段 | P0 | P1 | P2 |
|---|---:|---:|---:|
| 首次响应 | ≤ 1h | ≤ 4h | ≤ 24h |
| 遏制完成 | ≤ 4h | ≤ 24h | ≤ 72h |
| 根因确认 | ≤ 24h | ≤ 72h | ≤ 1 周 |
| 修复上线 | ≤ 48h | ≤ 1 周 | 按排期 |
| 复盘报告 | ≤ 1 周 | ≤ 2 周 | 可选 |

#### 证据保全步骤

1. **保留日志**：立即将相关应用日志、访问日志、审计日志、容器日志复制到只读存储（如 WORM bucket）。
2. **镜像与快照**：对受影响主机/容器生成内存转储、磁盘快照、容器镜像哈希（SHA-256）。
3. **网络证据**：保存负载均衡/CDN/WAF 访问日志、TLS 指纹、源 IP 列表、请求采样。
4. **时间线记录**：记录检测时间、遏制时间、关键操作、涉及人员，确保证据链完整。
5. **访问控制**：限制证据存储的访问权限，仅事件响应团队可读，防止二次泄露或篡改。
