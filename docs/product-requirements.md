> 关联文档: [架构设计](caddy-multi-tenant-architecture.md) | [系统架构](caddy-system-architecture.md) | [状态流转](caddy-state-transitions.md)

## 1. 产品定位

### 1.1 一句话描述

Portunus 是一个面向运维团队的多租户 Caddy 反向代理管理平台，提供项目级隔离的域名管理、代理配置、上游健康监控和 AI 辅助运维能力。

### 1.2 解决的问题

| 痛点 | 现状 | Portunus 方案 |
|---|---|---|
| Caddy 配置手动编辑 | 直接改 JSON/Caddyfile，无版本管理 | Web UI + API 管理，配置版本化、可回滚 |
| 多团队共享 Caddy | 一个 Caddy 实例多团队混用，无隔离 | 项目级 @id 隔离，RBAC 权限控制 |
| 配置变更无审计 | 不知道谁改了什么、何时改的 | 全操作审计日志，含 MCP 工具调用追踪 |
| 故障排查困难 | Caddy 配置漂移难以发现 | 配置漂移检测定时任务，checksum 比对 |
| 运维门槛高 | 需要熟悉 Caddy 配置语法 | AI 辅助运维，自然语言配置 |

### 1.3 目标用户

| 用户角色 | 典型画像 | 核心诉求 |
|---|---|---|
| 运维工程师 | 管理多个 Caddy 实例，需配置反向代理 | 批量管理域名和代理，快速变更 |
| 技术负责人 | 关注安全和合规 | 权限隔离、操作审计、配置回滚 |
| 开发团队 Lead | 团队需要独立的代理配置 | 项目隔离、自助管理、不互相影响 |
| AI 运维助手用户 | 希望用自然语言操作 | 通过对话完成配置，降低门槛 |

### 1.4 非目标（明确排除）

- 不替代 Caddy 作为数据面，仅提供控制面
- 不提供 DNS 解析管理（仅代理配置）
- 不提供 WAF/CDN 功能
- 不提供流量监控/分析（仅配置管理 + 健康检查）
- MVP 不支持多 Caddy 集群（单实例优先）

## 2. 用户故事

### 2.1 P0 — MVP 必须

#### US-01: 用户注册与登录

> 作为运维工程师，我希望通过邮箱注册账号并登录系统，以便开始管理我的反向代理。

**验收标准**：
- [ ] 邮箱+密码注册，密码强度校验（≥ 8 位，含字母+数字）
- [ ] 注册后状态为 `pending`，需邮箱验证链接激活
- [ ] 验证链接 24h 有效，过期需重新发送
- [ ] 登录后获取 JWT（access_token 15min + refresh_token 7d）；前端在 access_token 接近过期时自动使用 refresh_token 静默续期，用户无感知。
- [ ] 连续 5 次密码错误后锁定 15 分钟
- [ ] 支持 GitHub/Google OAuth 登录（阶段 2）

#### US-02: 创建项目

> 作为技术负责人，我希望创建一个项目，以便隔离管理团队的反向代理配置。

**验收标准**：
- [ ] 每个用户可免费创建 3 个项目
- [ ] 创建时指定项目名称和描述
- [ ] 创建者自动成为项目 `owner`
- [ ] 项目配额：最多 20 个域名/项目（可配置）
- [ ] 项目创建后状态为 `active`

#### US-03: 添加域名

> 作为运维工程师，我希望在项目中添加一个域名并配置反向代理，以便 Caddy 开始代理该域名。

**验收标准**：
- [ ] 输入域名名称（唯一性校验，同一项目不可重复；域名名称需全局唯一性校验，同一 Caddy 实例上不可重复，防止 host 冲突）
- [ ] 配置一个或多个上游地址（`host:port` 格式校验）
- [ ] 选择负载均衡策略（random/round_robin/least_conn）
- [ ] 创建后控制面在 5 秒内完成配置下发，Caddy 零停机热加载生效
- [ ] 域名状态从 `creating` → `active`，失败则 `error` 并显示原因
- [ ] 创建失败时数据库不留残留记录（事务回滚 + Caddy 清理）

#### US-04: 查看域名列表

> 作为运维工程师，我希望查看项目下所有域名及其状态，以便快速了解整体情况。

**验收标准**：
- [ ] 展示域名名称、状态（颜色标记）、上游数量、创建时间
- [ ] 支持按状态筛选
- [ ] 支持按名称搜索
- [ ] 支持分页（默认 20 条/页）
- [ ] 状态实时反映 Caddy 运行态

#### US-05: 修改反向代理配置

> 作为运维工程师，我希望修改域名的反向代理配置（负载均衡策略、Header 等），以便调整代理行为。

**验收标准**：
- [ ] 修改负载均衡策略后立即生效
- [ ] 修改过程中 Caddy 配置不中断（利用 Etag 乐观锁）
- [ ] 修改失败时自动回滚到上一个配置
- [ ] 操作记录在审计日志中

#### US-06: 添加/移除上游

> 作为运维工程师，我希望动态添加或移除上游服务器，以便在扩缩容时无需停机。

**验收标准**：
- [ ] 添加上游时 Caddy 自动纳入健康检查
- [ ] 移除上游时 Caddy 自动停止转发到该上游
- [ ] 同一代理下上游地址不可重复
- [ ] 操作通过 `POST /id/` 追加模式，不影响其他上游

#### US-07: 删除域名

> 作为运维工程师，我希望删除不再使用的域名，以便释放资源和 Caddy 配置。

**验收标准**：
- [ ] 删除前确认提示（前端二次确认）
- [ ] 删除后 Caddy 中对应 @id 配置被清理
- [ ] 删除后映射表中记录被清理
- [ ] 如果有活跃的共享关系，需先撤销共享
- [ ] 删除操作仅 `owner` 和 `admin` 可执行

#### US-08: 邀请团队成员

> 作为技术负责人，我希望邀请团队成员加入项目并分配角色，以便团队协作管理。

**验收标准**：
- [ ] 通过邮箱邀请新成员
- [ ] 邀请链接 24h 有效
- [ ] 可分配角色：admin / editor / viewer
- [ ] 被邀请人接受后状态为 `active`
- [ ] owner 不可被移除（需先转移所有权）
- [ ] 邀请记录在审计日志中

#### US-09: 查看审计日志

> 作为技术负责人，我希望查看项目的操作审计日志，以便追踪配置变更和排查问题。

**验收标准**：
- [ ] 展示操作时间、操作人、操作类型、资源、结果
- [ ] 支持按操作类型筛选（create/update/delete/read）
- [ ] 支持按时间范围查询
- [ ] 支持按操作人筛选
- [ ] 日志保留 90 天

#### US-10: 查看上游健康状态

> 作为运维工程师，我希望查看域名的上游健康状态，以便及时发现故障。

**验收标准**：
- [ ] 展示每个上游的 healthy/unhealthy 状态
- [ ] 状态来源为 Caddy 被动健康检查
- [ ] 控制面轮询间隔 ≤ 60s
- [ ] 代理整体状态自动反映：healthy/degraded/unavailable
- [ ] 前端展示最近一次检查时间

### 2.2 P1 — 阶段 2

#### US-11: 域名共享

> 作为技术负责人，我希望将域名共享给其他项目，以便跨团队协作。

**验收标准**：
- [ ] 共享时可设置权限：只读 / 可编辑
- [ ] 目标项目需确认接受（pending → active）
- [ ] 共享后目标项目可在域名列表中看到（标记为"共享"）
- [ ] 源项目可随时撤销共享
- [ ] 共享可设置过期时间
- [ ] 被共享方在 edit 模式下修改上游地址时，变更会记录审计日志并通知源项目 owner；撤销共享后，被共享方未提交的修改将被丢弃

#### US-12: 项目冻结与解冻

> 作为 system_admin，我希望冻结违规或异常的项目，以便暂停其操作但不删除数据。

**验收标准**：
- [ ] 冻结后项目所有写操作被拒绝
- [ ] 冻结后域名仍正常运行（不影响数据面）
- [ ] 冻结后项目所有写操作被拒绝，但用户在其他项目中的会话不受影响；用户在该项目下的权限被临时暂停，解冻后自动恢复
- [ ] 解冻后恢复正常

#### US-13: API Token

> 作为开发工程师，我希望创建 API Token 以便通过 CLI/CI/CD 管理域名配置。

**验收标准**：
- [ ] Token 创建后仅展示一次明文（SHA-256 哈希存储）
- [ ] Token 展示前缀（如 `tok_abc1****`）用于识别
- [ ] 可设置 Token 过期时间
- [ ] 可设置 IP 白名单
- [ ] 可随时撤销
- [ ] Token 绑定到特定项目和权限范围

#### US-14: 配置快照与回滚

> 作为运维工程师，我希望回滚到之前的配置版本，以便快速恢复。

**验收标准**：
- [ ] 每次配置变更自动保存快照
- [ ] 可查看历史配置版本
- [ ] 可回滚到任意历史版本
- [ ] 快照保留 90 天
- [ ] 回滚操作记录在审计日志中

### 2.3 P2 — 阶段 3

#### US-15: AI 辅助运维

> 作为运维工程师，我希望通过自然语言对话完成域名配置，以便降低操作门槛。

**验收标准**：
- [ ] 支持自然语言指令（如"给 example.com 添加一个上游 10.0.0.2:8080"）
- [ ] AI 通过 MCP 工具执行操作，返回执行结果
- [ ] 高风险操作（删除、修改）需用户确认
- [ ] 对话历史可查看
- [ ] 支持上下文理解（"再添加一个"指代上一个域名）

#### US-16: 配置漂移检测

> 作为技术负责人，我希望系统自动检测配置漂移，以便发现未经授权的变更。

**验收标准**：
- [ ] 默认可配置，建议 5 分钟检测一次，变更后主动触发一次全量比对
- [ ] 检测到漂移时标记为 `drift` 状态
- [ ] 通知项目 owner 和 system_admin
- [ ] 可手动触发漂移修复（用控制面快照覆盖 Caddy 配置）
- [ ] 漂移检测记录在审计日志中

#### US-17: OAuth 登录

> 作为用户，我希望使用 GitHub/Google 账号登录，以便免密码快速登录。

**验收标准**：
- [ ] 支持 GitHub OAuth
- [ ] 支持 Google OAuth
- [ ] OAuth 用户 `password_hash` 为 NULL
- [ ] 首次 OAuth 登录自动创建账号（状态为 `active`）
- [ ] 已有邮箱的用户可绑定 OAuth 账号

## 4. 数据模型概要

> 完整 DDL 详见 [架构设计文档](caddy-multi-tenant-architecture.md) §3.1

### 4.1 核心实体关系

```
User ──┬── project_members ──┬── Project
       │                     │
       │                     ├── Domain ──┬── ProxyConfig ── Upstream
       │                     │            │
       │                     │            └── DomainShare ── (target) Project
       │                     │
       │                     ├── Invitation
       │                     └── AuditLog
       │
       ├── ApiToken
       └── OAuthAssociation
```

### 4.2 关键实体

| 实体 | 说明 | 关键状态 |
|---|---|---|
| User | 系统用户 | pending / active / suspended / deleted |
| Project | 项目，资源隔离的基本单元 | active / suspended / deleting / error / deleted |
| Domain | 域名，关联到项目 | creating / active / updating / disabled / error / deleting / deleted |
| ProxyConfig | 反向代理配置 | active / updating / degraded / unavailable |
| Upstream | 上游服务器 | active / disabled / removed |
| ProjectMember | 项目成员 | active / removed / left |
| DomainShare | 域名共享 | pending / active / revoked / expired / rejected |
| Invitation | 成员邀请 | pending / accepted / rejected / expired |
| ApiToken | API 令牌 | active / revoked / expired |

> 完整状态机详见 [状态流转文档](caddy-state-transitions.md)

| 共享 | `/api/v1/projects/:id/domains/:did/share*` + `/shares/*` | 4 | ✅ |
| 审计 | `/api/v1/projects/:id/audit-logs` | 1 | ✅ |
| MCP | `/mcp` | — | Token |

### 5.2 统一响应格式

```json
{
    "code": 0,
    "message": "success",
    "data": { ... },
    "request_id": "req_abc123",
    "timestamp": "2026-07-25T10:00:00Z"
}
```

### 5.3 错误码体系

| HTTP | 错误码 | 说明 |
|:---:|:---:|---|
| 400 | 40001 | 参数校验失败 |
| 401 | 40101 | 未认证 / Token 无效 |
| 401 | 40102 | Token 已过期 |
| 403 | 40301 | 无权限 |
| 403 | 40302 | 项目已冻结 |
| 404 | 40401 | 资源不存在 |
| 409 | 40901 | 资源已存在 |
| 409 | 40902 | 状态冲突（乐观锁失败） |
| 429 | 42901 | 请求频率超限 |
| 500 | 50001 | 内部错误 |
| 502 | 50201 | Caddy 不可达 |

## 附录 A: 术语表

| 术语 | 定义 |
|---|---|
| 项目 (Project) | 资源隔离的基本单元，包含域名、代理、成员等 |
| @id | Caddy 配置中的唯一标识符，用于精确寻址和修改 |
| 控制面 | Portunus 服务本身，管理 Caddy 配置 |
| 数据面 | Caddy 实例，实际处理流量转发 |
| @id 映射 | 控制面数据库 ID 到 Caddy @id 的映射表 |
| 配置漂移 | Caddy 运行态配置与控制面记录不一致 |
| 沙箱预检 | 使用 `POST /load` 尝试加载配置，失败自动回滚 |
